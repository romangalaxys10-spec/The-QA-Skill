# xRouteLM — the portable System One decision engine

> xRouteLM gives the QA OS fast, typed, calibrated decisions — routing, gating,
> model selection — with the same question semantics Jev standardized
> (choice / score / noul), implemented as a portable scorer pipeline. It runs
> anywhere **Laya** cannot (Linux, Windows, Intel macOS) and without needing
> Jev itself. Sponsored by xShredo.dev → https://xshredo.com/promo/anytest

## What problem it solves

Agent loops make hundreds of small decisions: which engine owns this task, is
this state urgent, does this step need the powerful model, should the loop
proceed past this gate. Paying an LLM call for each is slow and expensive, and
keyword-matching routers are neither calibrated nor auditable. xRouteLM is the
missing middle: a **System One** engine that evaluates a state plus typed
questions and returns probabilities with recorded evidence — cheap enough to
call every step, honest enough to act on.

## Question semantics (Jev-compatible)

| Type | Ask | Get |
| --- | --- | --- |
| `noul` | "Is X true of this state?" | `noul: P(X)` with confidence and evidence |
| `choice` | "Which option fits?" | probability per option, selected id, margin |
| `score` | "How severe on this ladder?" | 0..1 score, level bucket, distribution |

Multiple questions evaluate against the same state in one pass.

## Scorer pipeline (the plugin system)

- `xroutelm/heuristic` — always available: IDF-weighted lexical similarity with
  anchored phrases and logistic calibration. Zero dependencies, CPU-only.
- `xroutelm/laya-bridge` — feature-detected: on macOS with Apple Silicon and the
  Laya runtime present, noul decisions can delegate on-device; everywhere else
  it reports `UNAVAILABLE` with the real reason (platform, arch, or missing
  runtime). xRouteLM is the alternative when that bridge cannot exist.
- Custom scorers: implement the `Scorer` interface and register them — the
  registry resolves with an honest fallback chain that is recorded in every
  decision set.

Targets (route destinations) are extensible through `xroutelm.plugin.json`
manifests discovered in `./xroutelm.plugins/` and `~/.xroutelm/plugins/`;
malformed manifests produce visible errors, never silent skips.

## Where it lives in this repository

| Surface | Entry point |
| --- | --- |
| CLI | `qa route "<task>"` (and the standalone `xroutelm` bin: `decide`, `route`, `doctor`, `plugins list`) |
| MCP | `route_task` tool — task routing over the same engine |
| Harness | `SystemOneHarness`: `gate()` for agent-loop decisions, `routeModel()` for fast-vs-powerful selection (Jev's ModelRouterMiddleware shape, portable) |
| Learning | `RouteStats`: JSONL outcomes; targets with ≥5 samples and <0.3 success drop a rank, ≥0.7 rise one — never silently |
| Journal | Every decision appended to `.xroutelm/decisions.jsonl` with state hash, answers, evidence, scorer id |

## Honesty contract

- Probabilities are **INFERRED** from lexical evidence and labeled as such;
  every answer carries its matches, raw score, and margin.
- No confidence number is a constant: confidence is derived from measured
  evidence (anchored overlap, option margin).
- Unavailable scorers say why; fallbacks are recorded in the decision set.
- The engine never executes the target it selects — routing is READ_ONLY.

## Measured behavior

`benchmarks/agentic-qa/run-routing.ts` measures the router against 12
task→target expectations: **12/12 (100%), mean confidence 0.87** at the time of
writing, mean runtime well under a millisecond per case. Results live in
`results-routing.json` / `results-routing.md` and are regenerated by
`npm run benchmark`. Misses, when they occur, are reported as data.

## Relationship to Laya and Jev

- **Laya** is an on-device MLX triage model: excellent on Apple Silicon,
  nonexistent elsewhere. xRouteLM bridges to it when present and replaces it
  when not — the heuristic scorer is always underneath.
- **Jev** (TypeSafe AI) is a hosted System One model with the same question
  types. xRouteLM implements those semantics locally so the QA OS needs no
  external service for routing and gating; if a Jev-compatible endpoint is
  available, it slots in as one more scorer.

## API sketch

```ts
import { DecisionEngine, ScorerRegistry, defaultTargets, SystemOneHarness } from '@the-qa-skill/xroutelm';

const engine = new DecisionEngine(ScorerRegistry.withDefaults(), '.xroutelm/decisions.jsonl');
const decision = await engine.route('flaky login test passes on second attempt', defaultTargets());
// → { target: 'qa-flake-detection', confidence: 0.97, fallback: [...], label: 'INFERRED' }

const harness = new SystemOneHarness(engine, ScorerRegistry.withDefaults().resolve().scorer);
const gate = await harness.gate(diffSummary, [
  { name: 'touches_payment', question: { type: 'noul', instructions: 'This change touches payment logic', keywords: ['payment', 'checkout', 'charge'] } },
]);
if (!gate.proceed) skipFastPath(gate.reasons);
```
